# Private World media sync production checklist

## Identity and authorization

- [ ] Firebase Authentication contains exactly the two authorized accounts.
- [ ] Each Firebase UID is present in Supabase `space_members` for the intended space.
- [ ] The Replit API validates Firebase ID tokens before every media operation.
- [ ] The API derives `owner_id` from the verified token and never trusts a client-supplied owner.
- [ ] The API checks `space_id` membership before reading or mutating media.
- [ ] Invalid, expired, and revoked Firebase tokens return HTTP 401.
- [ ] A user cannot read, update, or delete media belonging to another space.

## Supabase and Storage

- [ ] `001_media_sync.sql` has been reviewed and applied to the intended Supabase project.
- [ ] `private-world-media` is private.
- [ ] Anonymous Storage policies are absent.
- [ ] Storage paths are generated by the server and contain generated media IDs.
- [ ] Original files and thumbnails use separate paths.
- [ ] Signed URLs have short expirations and are never stored as permanent public URLs.
- [ ] Service-role credentials exist only in Replit server secrets.
- [ ] No service-role key appears in Expo variables, source control, build artifacts, or Android resources.
- [ ] Database backups and Supabase retention settings are configured.

## Client and Android release

- [ ] The application is tested in an Expo development build, not Expo Go.
- [ ] Android 12 and earlier storage permission behavior is verified.
- [ ] Android 13 image/video permission behavior is verified.
- [ ] Android 14 full and partial media access behavior is verified.
- [ ] Permission revocation pauses synchronization without deleting cloud media.
- [ ] WorkManager network and charging constraints behave as configured.
- [ ] The app does not use hidden media access, unrestricted background services, or permission bypasses.
- [ ] Release builds do not include development API endpoints or verbose token/error logging.

## Migration and rollback

- [ ] Run the migration script without `--write` first.
- [ ] Review every skipped record and owner mapping.
- [ ] Confirm `PRIVATE_WORLD_OWNER_MAP` maps display names to the correct Firebase UIDs.
- [ ] Run a limited write migration with `--limit` before the full migration.
- [ ] Verify migrated records and Storage objects before disabling legacy reads.
- [ ] Keep Firestore photos unchanged during the migration window.
- [ ] Keep a migration log containing source document IDs and generated media IDs.
- [ ] Roll back by disabling new gallery reads, not by deleting cloud media automatically.
- [ ] Delete legacy data only after an explicit, separately approved cleanup operation.

## Operational monitoring

- [ ] Monitor API 401, 403, 429, and 5xx responses.
- [ ] Monitor signed URL and Storage failures.
- [ ] Monitor failed queue items and retry rates.
- [ ] Monitor large-video upload failures separately.
- [ ] Monitor scan duration, memory, battery, and network usage on representative devices.
- [ ] Test with hundreds, thousands, and tens of thousands of media items.
