Build a complete private Android-first mobile application from scratch.

This is NOT a public website. It is a private digital space designed to be used by exactly two people.

The app should feel like a beautiful combination of:

- private messaging app
- shared memory journal
- photo album
- music player
- digital scrapbook
- personal relationship/friendship space

The app should be highly customizable and cloud-synchronized.

CORE REQUIREMENT

There are two users:

1. Owner/Admin
2. Private User

Both users have their own login.

Anything uploaded or created by one user should be stored in the cloud and become available to the other user's app.

For example:

Owner uploads a photo
→ photo goes to cloud storage
→ database records the photo
→ other user's app receives/syncs the photo
→ photo appears in their Gallery/Memory section.

This same principle must work for memories, messages, letters, songs, journal entries, etc.

Do NOT build this as a collection of hard-coded React pages.

The application must be CONTENT-DRIVEN.

Adding content later must NOT require modifying source code.

---

TECHNOLOGY

Use a modern mobile-friendly architecture.

Preferred stack:

- React
- TypeScript
- Vite
- Tailwind CSS
- Capacitor for Android packaging
- Framer Motion for animations
- Firebase Authentication
- Firebase Firestore
- Firebase Storage
- Firebase Cloud Messaging where appropriate

Use Firebase because this app requires:

- authentication
- cloud database
- cloud file storage
- real-time synchronization
- secure access rules

Structure the application so Firebase configuration can be added through environment variables.

Do NOT expose private credentials in source code.

---

AUTHENTICATION

Create a private authentication system.

Only two authorized accounts should be able to access the application.

Implement:

- Login
- Logout
- Persistent session
- Loading state
- Invalid-login handling
- Protected routes
- User roles

Roles:

OWNER
USER

The OWNER has additional management capabilities.

Do not rely on simply hiding the app or keeping a secret URL.

Use real authentication and database security rules.

PRIVATE CHAT

Build a real-time private messaging system between the two users.

Users should be able to:

- Send text messages
- Receive messages
- See timestamps
- See sent/received state
- See read/unread state
- Scroll through conversation history
- Send messages without leaving the app

The conversation must sync through Firestore.

If I send:

"Good morning ❤️"

from my phone, it should appear in her app.

If she replies:

"Good morning 😊"

it should appear on my phone.

Messages must persist after closing and reopening the app.

Structure the database cleanly so future features such as:

- image messages
- voice messages
- reactions
- reply-to-message

can be added later.

For now, implement text messaging properly.

PHOTO GALLERY

Create a shared cloud photo gallery.

Users can:

- Upload photos
- Add captions
- Add dates
- Edit captions
- Delete photos if permitted
- View photos fullscreen
- Browse photos in a beautiful grid
- Open individual photos
- See who uploaded them

When one person uploads a photo, it must become available to the other person after synchronization.

Store actual image files in Firebase Storage.

Store metadata in Firestore.

Do NOT store large image files directly inside Firestore.

Handle:

- upload progress
- failed uploads
- missing images
- slow connections

Gracefully.

messages
memories

songs

---

SECURITY

Create Firestore Security Rules so:

- Only authenticated users can access the app.
- Only the two authorized accounts can access shared data.
- Users cannot access another user's unrelated data.
- Storage files are protected.
- Owner-only operations require OWNER role.
- A random authenticated account cannot simply join the private space.

Never trust frontend role checks alone.

Enforce important permissions in Firebase Security Rules.
